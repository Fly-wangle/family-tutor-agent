# 安装与迁移

## 提供与不提供

提供：项目规则、空知识库、可复制 Prompt、私有工作区初始化和校验工具。

不提供：AI 客户端安装包、账号、API、语音引擎、系统权限、已部署定时任务或真实教材。初始化器无需账号、不联网，不读旧家庭工作区；启动 Agent 后是否使用云端由你的客户端决定。

使用支持本地项目规则的 Agent 时，以实际文件读取为准；其他客户端需要家长手动提供规则、最小学生档案和当前简报。不要假定所有工具都会自动加载 AGENTS.md，也不要只用“记住了”作为验收。

## 创建一个家庭工作区

在可信的公开模板副本根目录运行，Python 3.9 或更新版本即可：

```bash
python3 scripts/init_workspace.py --dest ../my-family-tutor
```

目标必须不存在或为空，并位于模板目录之外。原有数据不被覆盖；若选错目标，换一个新目录，不删除原有内容。

生成内容包括 AGENTS、简短工作区 README、教学方法、空记录、materials 目录与默认忽略全部文件的 `.gitignore`。不会拷贝 `.git`、真实附件、账号或旧会话；不会迁移任何孩子的学习表现。示例仅在公开模板的 `examples/` 参考，不作为学生实际表现导入。

家长先填写：

1. `knowledge-base/student-profile.md`：昵称、年级、兴趣、教材、口语课堂称呼。
2. `knowledge-base/curriculum/`：明确版本、已确认进度、来源日期，未知保留未知。
3. `knowledge-base/thread-policy.md`：在客户端手动建好线程，再登记实际入口。口语称呼与语音方式要逐个确认。
4. `knowledge-base/integrations/README.md`：可读取的数据源、读取授权与缺失项；默认只读。

给第二个孩子使用时重新运行初始化器到另一个目录，重新填写档案和会话入口。不要复制现有孩子的知识库、转写、allowlist 或后台服务状态。

## 最小验收

- 家长线程能说明学生昵称、教材版本与未知项，并指出实际读取的文件；不把示例学情当事实。
- 各科线程能读取同一个家庭的资料，儿童口吻引导；一道未完成题收首答，一道已完成题能按请求核对。
- 原始附件不清晰时标未知；通知里的待办不直接写成掌握。
- 先做短句文字教学，再按 [语音检查](tts.md) 试听每个需要发声的线程。家长/复盘静音，Live/TTS 不叠加。
- Live 必须在两个独立新语音会话中验证称呼、英语主导与中文搭桥；普通文字答对不替代该检查。
- 复盘能引用本轮实际可见的孩子输出，产生一张下一课递进卡；没有转写就标口语不可观测，不虚构进步。

本仓库的测试只验证模板工具和规则一致性，不能证明新设备上的声音、记忆或教学效果。

## 可选自动化

文字教学与声音验收后，家长才指定时间、时区、学科目标、固定目标线程和无人值守截止时间。每个任务在自己的固定线程直接交付，不新开每日线程，也不改变会话模型或访问权限。

分开核对：调度是否触发、是否交付完整内容、是否实际出声。三个结果不能互相替代；客户端是否能自动说话需要现场验证。周末、节假日和未完成任务如何处理都由家长选择，不沿用其他家庭的时间表。

## 后续更新

1. 保持公开模板目录不含真实资料，在这里执行 `git pull --ff-only`，先查看 CHANGELOG。
2. 在家庭工作区之外做私有备份；备份包含附件时也不能进入公开仓库。
3. 对照 AGENTS、方法文件与索引差异，小步合并；不要覆盖学生档案、课程进度、错题、报告、线程入口和口语当前简报。
4. 重新做上述最小验收，再开始孩子的正式学习。旧的 Live 会话未必热加载新规则，应重新开启并检查。

需要 Git 管理真实资料时，另建访问受控的私有仓库并人工调整忽略规则。公开仓库里的任何分支都不是私有空间。

## 常见问题

**为什么没声音？** 初始化只创建教学文件，没有安装 TTS。先确认实际服务、允许的线程、Live 互斥、音频输出设备，再试听；不要反复改教学规则。

**为什么老师不知道最新安排？** 先确认来源是否可读取、是否已归档、对应会话是否实际读到。聊天里的承诺不等于文件读写成功。

**能装到亲属电脑吗？** 可以用新工作区从零配置；目标设备、账号登录、权限与语音需要当地家长完成或明确授权。不要共享账号凭证或现有孩子的真实记录。
